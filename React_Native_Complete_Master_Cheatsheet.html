2.1

ScrollView vs FlatList Memory Recycling

ScrollView mounts all items at once; FlatList recycles unmounted cells outside the viewport.

ScrollView (Eager: 10,000 items in RAM → OOM Crash): [Item 1][Item 2][Item 3] ... [Item 10000] FlatList (Virtualized: only ~10 visible rows in RAM): ▲ unmounted, memory freed ┌──────────────────┐ │ Item 4 (visible) │ │ Item 5 (visible) │ ← constant memory footprint │ Item 6 (visible) │ └──────────────────┘ ▼ queued for recycling
import React from 'react'; import { FlatList, Text } from 'react-native'; export const FeedList = ({ data }) => ( <FlatList data={data} keyExtractor={(item) => item.id.toString()} renderItem={({ item }) => <Text>{item.title}</Text>} initialNumToRender={10} maxToRenderPerBatch={5} windowSize={5} removeClippedSubviews={true} /> );

3.1

AppState Lifecycle & Memory Garbage Collection

Screens in the mobile navigation stack remain mounted in memory when left.

import React, { useState, useEffect, useRef } from 'react'; import { AppState } from 'react-native'; export const LocationTracker = () => { const [state, setState] = useState(AppState.currentState); const timerRef = useRef(null); useEffect(() => { const sub = AppState.addEventListener('change', (next) => setState(next)); timerRef.current = setInterval(() => console.log('Tracking GPS'), 1000); return () => { sub.remove(); clearInterval(timerRef.current); // 🛑 Mandatory cleanup prevents memory leaks }; }, []); };
Memory Leak Trap

Timers or subscriptions without cleanup functions keep running after users navigate away, causing battery drain and background crashes.

Worklets & Pan Gestures on UI Thread
